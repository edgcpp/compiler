[GH #500]
Empty enclosing packs in generic lambdas

A pack expansion in a generic lambda nested in a template instantiation could
produce an error node in the IL when it referenced a lambda parameter pack
before an empty enclosing parameter pack.  Empty enclosing packs are now
handled correctly regardless of the order of the pack references.  Spurious
warnings from prototype instantiations in such cases are also suppressed.  For
example, with --c++20 -tused:

  template<int... Is> void f() {
    []<int... Js>() { ((Js * Is) * ... * 1); };
  }
  template void f<>();  // Previously produced an error node in the IL.
