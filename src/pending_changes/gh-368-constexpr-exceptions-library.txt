[GH #368]
C++26: Library support for exceptions in constant evaluation

The library support of P3068R6 is now implemented in C++26 mode (or with
--set_flag=constexpr_exceptions): std::current_exception,
std::rethrow_exception, and std::uncaught_exceptions can be called during
constant evaluation (even if the library declares or defines them without
"constexpr"), and so can std::exception_ptr operations if that class has a
single nonstatic data member of pointer type (as in the GCC C++ standard
library).  For
example, with --c++26 and a library that supports this:

  #include <exception>
  constexpr int f() {
    std::exception_ptr p;
    try {
      throw 42;
    } catch (...) {
      p = std::current_exception();
    }
    try {
      std::rethrow_exception(p);
    } catch (int i) {
      return i;
    }
  }
  static_assert(f() == 42);  // Previously an error; now okay.

In g++ modes with gnu_version >= 160000, the builtins
__builtin_eh_ptr_adjust_ref, __builtin_current_exception, and
__builtin_uncaught_exceptions, which the GCC C++ standard library uses for
this, are now supported.

In addition, a dynamic_cast to a reference type that fails, typeid applied to
a null glvalue, and an array new-expression with an invalid number of elements
now throw std::bad_cast, std::bad_typeid, and std::bad_array_new_length,
respectively, during constant evaluation, provided that the definition of the
corresponding class is available and it has a constexpr default constructor.
Otherwise, those cases are diagnosed as before.

An exception object that is still referred to by a std::exception_ptr at the
end of the evaluation causes the evaluation to not be constant.
