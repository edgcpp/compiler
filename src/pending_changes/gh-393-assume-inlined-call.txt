[GH #393]
IL write/read check failure for [[assume]] with an inlinable call

When lowering the argument of an [[assume]] attribute, the empty statement
that carries the attribute was passed to the lowering of the expression as
if the argument were the statement's own expression.  If the argument was a
call that could be inlined (for example, a call to a constexpr function),
the inlining turned the statement into a block and the attribute was lost.
In a debug build, the IL write/read check then failed with "not all
expected entries were read".  For example:

  constexpr bool g(bool b) { return b; }
  constexpr int f(bool b) { [[assume(g(b))]]; return 1; }

The argument is now lowered without a statement, so the attribute is kept.
