[GH #402]
Variables declared before a case label in constant evaluation

During constant evaluation, a variable declared (without initializer) after
one case label of a switch statement and used after a subsequent case label
was treated as inaccessible when the switch statement transferred control
to the subsequent label.  The same happened for a variable declared without
initializer in the init-statement of an if- or for-statement whose
substatement contains the case label.  For example, with --c++20:

  constexpr int f() {
    switch (1) {
      for (int x; ;) {
      case 1:
        x = 3;
        return x;
      }
    }
    return 0;
  }
  static_assert(f() == 3);  // Previously failed.

This is now fixed.
