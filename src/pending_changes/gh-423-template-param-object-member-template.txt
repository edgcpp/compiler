[GH #423]
Class-type template parameters of enclosing templates in member templates

When an enclosing template (e.g., a class template) was instantiated, a
reference to one of its nontype template parameters of class type in the
signature of a member template was replaced by the template parameter
object.  When the member template's own template arguments were
substituted, that reference was then treated as a prvalue instead of as a
const lvalue.  As a result, taking its address caused deduction to fail, and
other uses (e.g., in a decltype operand) caused a spurious "unexpected
function type" error.  That is now fixed.  For example, with --c++20:

  struct A { int i = 0; };
  constexpr A a1{1};
  template <A V> struct S {
    template <typename T> static auto f(T t) -> decltype(t, &V);
    template <typename T> static auto g(T t) -> decltype(t, V);
  };
  using R1 = decltype(S<a1>::f(0));  // Previously, no instance matched.
  using R2 = decltype(S<a1>::g(0));  // Previously, "unexpected function
                                     // type" error.
