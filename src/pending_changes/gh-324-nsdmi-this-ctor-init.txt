[GH #324]
Implicit "this" in a default member initializer used by a constructor

The changes for GH #408 did not cover the case where a default member
initializer that contains an aggregate initialization of another object of
the same class is used by a constructor (an implicitly-defined default
constructor, possibly called for a base class or a member).  An implicit
use of "this" in the elements of the nested initialization still referred
to the nested object instead of to the object being constructed.  For
example:

  struct Y { unsigned k = 7; unsigned n = Y{2, k}.n; };
  struct D : Y { D() {} };
  unsigned n = D().n;  // n is now 7 (previously 2).

This is now fixed.
