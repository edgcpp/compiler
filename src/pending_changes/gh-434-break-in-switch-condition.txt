[GH #434]
GNU statement expressions and switch statements

In GNU modes, a break statement inside a statement expression that appears as
the value a switch statement switches on was bound to that switch statement
instead of (as with GCC and Clang) to the enclosing loop or switch statement.
Similarly, a case or default label in such a statement expression was
associated with that switch statement.  For example, with --g++ --c++20:

  int f(int y, bool c) {
    switch (y) {
    case 0:
      switch (({ if (c) break; 1; })) {
      case 1:
        return 10;
      }
      return 1;
    }
    return 2;
  }

f(0, true) returned 1 instead of 2.  Constant evaluation had the same
problem, and also let a switch statement complete a break statement executed
while computing the value it switches on.  This is now fixed.  Such a break
statement is now diagnosed if there is no enclosing loop or switch
statement, and such a case or default label now applies to an enclosing
switch statement (and is diagnosed as a transfer of control into a statement
expression).
