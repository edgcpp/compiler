[GH #506]
Pack expansions in nested generic-lambda template default arguments

A default template argument of a nested generic lambda could be rejected when a
pack expansion involving an enclosing pack was incorrectly treated as empty
before the lambda's template arguments were available.  Such defaults now
remain dependent until instantiation.  For example, with --c++20 -tused:

  template<int... Is> void f() {
    [](auto) {
      []<int... Js, typename U = int[((Js * Is) * ... * 1) - 2]>() {};
    };
  }
  template void f<2>();  // Previously a spurious array bound error, now okay.
