[GH #401]
break and continue in GNU statement expressions in constant evaluation

In GNU modes, a break or continue statement inside a statement expression
did not correctly transfer control out of the enclosing full-expression
during constant evaluation: the evaluation of the enclosing expression
continued with an indeterminate value for the statement expression, and the
enclosing loop or switch statement was not exited.  For example, with
--c++20 --gnu_version 130000:

  constexpr int f(int v) {
    int n = 0;
    for (int i = 0; i < 5; ++i) {
      n += ({ if (i == v) break; i; });
    }
    return n;
  }
  static_assert(f(3) == 3);  // Previously failed.

This is now fixed.  To that end, the interpretation of control transfers
(break, continue, and return statements, and the entry of a switch statement
at a case label) and of loops was reorganized.
