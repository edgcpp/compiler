[GH #484]
Lookup in default template arguments during partial specialization rescans

When a template argument list was checked during the rescan of a partial
specialization (e.g., when matching a partial specialization that uses
void_t), a default template argument of a class or variable template
named in that list was substituted in the context of the partial
specialization rather than that of the class or variable template.  Names
declared after the partial specialization but before the class or variable
template were therefore not found, and the substitution was wrongly
considered to fail.  (This only occurred when dependent name processing was
done, so Microsoft permissive mode was not affected unless --dep_name was
specified.)  That is now fixed.  For example, with --c++17:

  template<class...> using void_t = void;
  template<class, template<class...> class TT, class... P>
  constexpr bool ok_impl = false;
  template<template<class...> class TT, class... P>
  constexpr bool ok_impl<void_t<TT<P...>>, TT, P...> = true;
  namespace lib { template<class T> T&& declval() noexcept; }
  template<class T, class = decltype(&lib::declval<T&>())> struct A {};
  struct V {};
  static_assert(ok_impl<void, A, V>, "");  // Previously failed.
