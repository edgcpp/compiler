[GH #90]
GNU and Clang C++ modes: lifetime extension through a member of a temporary

When emulating GCC 9 or later or Clang 4 or later (in C++11 and later
modes), selecting a member of a class prvalue now produces an xvalue (Core
issue 616), as it already did in standard C++14 and later modes.  Binding a
reference to the member now extends the lifetime of the whole temporary.
For example, with --g++ --gnu_version=150000:

  struct A { int b; ~A(); };
  const int &r = A().b;  // A() was previously destroyed here.

Returning a pointer into a member of a class prvalue is now diagnosed also
when the class is trivially destructible.  For example, with --c++20:

  struct T { int b; int arr[2]; };
  T make();
  const int *f() { return &make().arr[1]; }  // Warning.

Constant evaluation also no longer treats every member of a class prvalue
as initialized when one is selected with "." or ".*".  Since C++20, a
constexpr constructor can leave members uninitialized, and reading such a
member is now diagnosed instead of producing an indeterminate value.  For
example, with --c++20:

  struct W { int n; constexpr W() {} };
  static_assert(W().n == 0);  // Error: n is uninitialized.

Constant evaluation now also marks each element of a GNU vector as
initialized when a whole vector value is stored (e.g., by a mem-initializer),
and copies the state of each element when an object containing a vector is
copied.  Subscripting such a vector could previously give a spurious "access
to uninitialized object" error.  Conversely, reading or copying a whole
vector subobject now requires each of its elements to be initialized.  For
example, with --g++ --c++20:

  typedef int V4 __attribute__((vector_size(16)));
  struct Y { V4 v; constexpr Y(V4 a) : v(a) {} };
  constexpr int f() { V4 a = {1, 2, 3, 4}; Y y(a); return y.v[3]; }
  static_assert(f() == 4, "");  // Previously rejected.
