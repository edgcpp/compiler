[GH #398]
dynamic_cast in constant evaluation requires public base class subobjects

During constant evaluation, the run-time checks of a dynamic_cast did not
require the operand to point to (or refer to) a public base class subobject
of the destination object (for a cast to a derived class) or of the most
derived object (for a cast to a sibling base class, which also requires the
destination type to be a public base class of the most derived type).
Instead, the accessibility of the base classes in the context of the cast
was checked.  For example, with --c++20:

  struct B { virtual void b() {} };
  struct D : private B {};
  struct F : D {};
  constexpr F f;
  static_assert(dynamic_cast<const D*>((const B*)&f) == nullptr);
                                              // Previously failed.

This is now fixed.
