[GH #281]
Explicit conversion functions before parenthesized aggregate initialization

The front end could incorrectly attempt parenthesized aggregate initialization
instead of considering an explicit conversion function when directly
initializing an aggregate in C++20 mode.  For example:

  struct D { float x, y; };
  struct S { explicit operator D() const; };
  D d(S{});  // Previously an error in C++20 mode.  Now okay.

That is now fixed.  The rule allowing explicit conversion functions in this
context comes from Core issue 899 and applies in C++11 and later modes.  The
failure occurred when C++20 parenthesized aggregate initialization was enabled.
