[GH #462]
decltype of template parameters in requires-expression parameter types

When a requires-expression appeared in a template other than a concept
definition (e.g., in a variable template initializer or a function template
body), decltype applied to a template parameter in the type of one of its
parameters was not substituted correctly.  The parameter then got an
unusable type, so that any requirement using it in an operation (e.g., a
call) was considered unsatisfied.  Similarly, in a member template of a class
template, decltype applied to a class-type template parameter of the class
template produced the const type of the template parameter object (rather
than the declared type of the template parameter) once the class template
was instantiated.  That is now fixed.  For example, with --c++20:

  struct A { int operator()() { return 0; } };
  template <auto F>
  constexpr bool b = requires(decltype(F) f) { f(); };
  static_assert(b<A{}>);  // Previously failed.
  template <auto F> struct S {
    template <int I> static constexpr bool m() {
      return requires(decltype(F) f) { f(); };
    }
  };
  static_assert(S<A{}>::m<1>());  // Previously failed.
